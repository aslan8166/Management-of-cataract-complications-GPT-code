# Ophthalmology LLM Temporal-Validity Study — Arm 1 engine

Bibliometric engine over a PubMed corpus that quantifies **how outdated the
tested LLM was by the time each ophthalmology LLM-evaluation paper was
published** (temporal validity of the evidence). This repo is **Arm 1** only;
Arm 2 (re-running tasks on the current frontier model) is out of scope until
Arm 1 is approved.

`AGENTS.md` is the source of truth for definitions and guardrails — read it
first. This README describes how the code implements it.

> **Stage 0 status (this PR):** scaffold + a 50-record pilot engine, built and
> unit-tested offline. **The live 50-PMID pull is currently BLOCKED** — this
> session's egress policy denies `eutils.ncbi.nlm.nih.gov` (proxy `CONNECT`
> 403). Everything except the live fetch runs and is tested; the pilot report
> below is produced from **bundled fixtures** (`make demo`). See
> [Known blocker](#known-blocker-ncbi-egress).

## Layout

```
config/query.txt            # approved PubMed Boolean query (corpus window: 2022-11-01+)
data/model_spine.csv        # SOLE source of truth for model release/deprecation dates
data/generation_index.csv   # frozen ordered minor-version index per family (derived)
data/review_queue.csv       # unresolved/ambiguous tested-model versions (human adjudication)
data/raw/<snapshot>/        # cached NCBI XML + retrieval_log.json (one dated snapshot per fetch)
src/fetch.py                # esearch+efetch via E-utilities (history server, backoff, cache)
src/parse_dates.py          # epub/edat/received/accepted extraction (priority order)
src/spine.py                # spine loader + family/minor-version/date derivation
src/extract_models.py       # title+abstract -> canonical spine IDs; route unresolved -> review
src/build_generation_index.py
src/report.py               # pilot report generator (+ --demo on fixtures)
tests/                      # pytest (mandatory for parse_dates + generation index)
outputs/                    # derived figures/tables/reports (regenerated by make)
Makefile                    # reproducible pipeline
```

## Guardrails honored (see AGENTS.md)

- **Spine is the only date authority.** Model IDs and dates come exclusively from
  `data/model_spine.csv`. Curated alias targets are validated against the spine at
  load time; nothing is invented. Anything unresolved is marked `UNVERIFIED`.
- **Never guess a version.** Unversioned "ChatGPT" → `chatgpt_unversioned`; a
  version that maps to >1 snapshot → `unresolved_version`; a bare family name →
  `family_only`. All routed to `data/review_queue.csv` for human adjudication.
- **PubMed only**, via NCBI E-utilities. Preprint-only / CS-venue-only papers are
  out of scope by design.
- **Every fetch is a dated snapshot.** `data/raw/<UTC-timestamp>/` holds the raw
  XML plus `retrieval_log.json` (exact + normalized query, PubMed's
  query_translation, retrieval timestamp, tool versions, returned PMID list,
  WebEnv/QueryKey). A re-pull is a NEW snapshot, never an overwrite.
- **Provisional dates surfaced, not relied on silently.** Two distinct trust
  signals per generation unit: `provisional` ("confirm on vendor blog" flagged)
  and `non_vendor_source` (Wikipedia/third-party).

## epub_date priority (parse_dates.py)

1. `Article/ArticleDate[@DateType="Electronic"]`  → basis `ArticleDate[Electronic]`
2. `History/PubMedPubDate[@PubStatus="epublish"]`  → basis `History[epublish]`
3. Fallback `Journal/JournalIssue/PubDate` (Y or Y/M; or a `MedlineDate` string)
   → basis `PubDate` / `PubDate[MedlineDate]`

`edat` (entrez) is recorded for **sensitivity analysis only**. Partial dates keep
their true precision (day/month/year); a missing day is never imputed.
`epub_date_clean` = day precision from ArticleDate[Electronic] or History[epublish].

## Generation index (collapsing rule) — REVIEW THESE ASSUMPTIONS

One unit per minor version; tiers and variants (Instant/Thinking/Pro/Codex/
mini/nano, context-size, vision, re-dated snapshots) add NO units. Ordered within
family by earliest release date. The exact, assumption-laden choices (OpenAI
o-series handling, Anthropic tier collapsing, Bard/PaLM inclusion,
Fable/Mythos placement, earliest-member dating) are documented in
`src/spine.py::derive_minor_version` and listed in
`outputs/pilot_report.md` §6. **These are the items to confirm before scaling.**

## Tests

```bash
make test
```

`tests/test_parse_dates.py` covers partial-date, MedlineDate-string, and
missing-ArticleDate records (AGENTS.md-mandated). `tests/test_generation_index.py`
asserts minor-version ordering and that variants add no units.
`tests/test_extract_models.py` asserts resolve-vs-review routing.

## Known blocker: NCBI egress

`src/fetch.py` is complete and correct, but in this environment outbound HTTPS to
`eutils.ncbi.nlm.nih.gov` is denied by the session's egress policy (proxy
`CONNECT` → 403). `make fetch` fails fast with that diagnosis and does **not**
retry or route around it. To run the real pilot, allow-list
`eutils.ncbi.nlm.nih.gov` for the environment (and optionally set `NCBI_API_KEY`),
then `make pilot`. The connected PubMed MCP server is **not** a substitute: it
caps Boolean queries at 20 operators (the corpus query has 23) and returns a
single flattened `publication_date` without the `ArticleDate`/`History` fields the
study depends on.
